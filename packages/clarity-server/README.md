# Skalpl Clarity Server (`clarity-server`)

Whitelabel backend, ingestion collector, and heatmap API for the Skalpl ecosystem, powered by the open-source Microsoft Clarity engine.

## 🚀 Features

- **100% Strict TypeScript**: All data models, database interfaces, API requests, and visualization responses are strongly typed.
- **Native Multi-Tenancy**: Built-in project/site isolation with domain allowlisting to prevent spam and data leakage.
- **High-Throughput Ingestion**: Returns `204 No Content` immediately. Decodes and processes telemetry asynchronously.
- **Zero-Overhead Clustering**: Delivers pre-aggregated `Activity` and `ScrollMapInfo` payloads designed for GPU-accelerated client-side canvas rendering via `clarity-visualize`.
- **SDK Delivery**: Serves the compiled `tracker.js` bundle directly with browser caching.

## 🛠️ API Contracts

### 1. Telemetry Ingestion (Visitor Browser)
- **`POST /api/v1/collect`**
  - **Headers**: `Content-Type: text/plain` (or `application/json`), `Origin: https://client-domain.com`
  - **Body**: Raw string payload generated by `clarity-js`
  - **Response**: `204 No Content`
  - The collector drops the payload when the project is unknown or inactive. It also drops it when `Origin` (or `Referer`) is missing or its host is not in `allowedDomains`. `"*"` allows any origin. An empty list allows none.
  - It also drops the payload when its page key matches an `excludePatterns` entry. Each pattern loses its scheme, query, hash, `www.` and trailing `/`, and is lowercased. `*` matches any characters, `/` included. The pattern must match the whole key.
  - Every drop is counted by project and reason: `unknown`, `inactive`, `origin`, `excluded`, `invalid`, `gunzip`. Counts are stored once a minute, with one log line per project and reason.
  - Device comes from the viewport width: below 768 px is `mobile`, below 1024 px is `tablet`, else `desktop`. A beacon without a width reuses the device of its page view. The user agent is the last fallback.

**Page key**: the lowercase host without a leading `www.`, plus the path without trailing slashes. The root is `host/`. No scheme, query or hash. A non-default port stays. Clicks, scrolls and snapshots are stored by page key.

### 2. Multi-Tenant Project Management
- **`POST /api/v1/projects`** or **`PUT /api/v1/projects/:id`** (upsert)
  - **Headers**: `X-Internal-Secret` (required)
  - **Body**:
    ```json
    {
      "id": "skalpl_store_alpha",
      "name": "Skalpl Store Alpha",
      "allowedDomains": ["store-alpha.skalpl.com", "www.store-alpha.skalpl.com"],
      "isActive": true,
      "excludePatterns": ["store-alpha.skalpl.com/thanks*"],
      "version": 1794390590217
    }
    ```
  - `id` is required on POST. On PUT it comes from the path; a body `id` must match it.
  - Omitted fields keep the stored value. A new project without `allowedDomains` gets `[]`.
  - `version` is the unix ms of the backend change. A version lower than the stored one returns `409 {"error":"stale_version","storedVersion":...}` and writes nothing. An equal version is applied again. A missing version is accepted and keeps the stored one.
  - **Response**: `201 Created` (new), `200 OK` (updated), `409` (stale), `400` (invalid body), `401` (bad secret)
- **`GET /api/v1/projects/:id`**: `{project, drops}`, where `drops` is `{reason: {count, lastAt}}`. A 404 for an unknown id still carries `drops`.
- **`GET /api/v1/projects/:id/pages`**: `{projectId, pages}`, newest `lastSeen` first. Each page is `{pageKey, pageUrl, firstSeen, lastSeen, views, clicks, excluded, devices}`. `pageUrl` is the last real URL seen. `views` counts page loads. `devices` holds `{views, clicks, lastSeen}` per device. Unknown project: 404.
- **`GET /api/v1/drops`**: drops not tied to a project (`gunzip`, `invalid`).

### Environment
- `DATABASE_URL`: required. It is passed to `pg` as is. For peer auth over the unix socket use `postgresql://user@%2Fvar%2Frun%2Fpostgresql/db`.
- `CLARITY_INTERNAL_SECRET`: required. The server does not start without it.
- `PORT`, `HOST`: listen address.
- `CLARITY_RETENTION_DAYS`: raw clicks and scrolls older than this are deleted at start and every 6 hours. Default 90.
- In production, `/demo` returns 404 and `/api/v1/demo/*` returns 403. Outside production, the demo reads `demo_local` through `/api/v1/demo/heatmaps/*` without the secret.

### 3. Heatmap Data (Skalpl Dashboard)
- Every route takes `projectId` and `pageKey`. A `pageUrl` is accepted instead and is turned into its page key. An unknown project returns 404.
- `device` is `desktop`, `mobile` or `tablet`. Omit it for all devices. Any other value returns 400. Responses carry `pageKey` and `device` (`null` when omitted).
- `from` and `to` are ISO 8601 with an offset (`2026-11-11T00:00:00+07:00`), or `Y-m-d` with `tz` (an IANA zone such as `Asia/Jakarta`, or `+07:00`). `from` is inclusive and `to` is exclusive; a `Y-m-d` `to` covers that whole day. Omit them for no bound. Anything else returns 400.
- Filters and retention use the server receive time. The browser clock is kept in `client_time`.
- **`GET /api/v1/heatmaps/click?projectId=...&pageKey=...&device=desktop&from=...&to=...`**
  - Returns: `HeatmapClickResponse` (`activity: Activity` array of `{ hash, selector, totalclicks, x, y, clicks, points }`).
- **`GET /api/v1/heatmaps/scroll?projectId=...&pageKey=...&device=desktop`**
  - Returns: `HeatmapScrollResponse` (`scrollMap: ScrollMapInfo[]` with percentage distribution). `averageFoldY` is the mean viewport height in px. With no sessions, `scrollMap` is `[]` and `averageFoldY` is `null`.
- **`GET /api/v1/heatmaps/snapshot?projectId=...&pageKey=...&device=desktop`**
  - Returns: `PageSnapshotResponse` containing the raw Discover DOM payload to pass into `visualizer.html()`. Without `device`, the latest snapshot across devices. 404 when there is none.

- **`GET /health`**: no auth. `200 {"status":"healthy","db":"ok"}`, or `503` when Postgres does not answer.

### 4. SDK Serving
- **`GET /tracker.js`**
  - Serves the minified `clarity.min.js` tracking bundle.

## 🏃 Running & Testing

```bash
# Build TypeScript
yarn build:server

# Run Integration Tests
yarn test:server

# Apply the schema (idempotent; run on every deploy before start)
DATABASE_URL=... yarn migrate:server

# Start Server
yarn start:server
```
